# استودیو — Sequence Flow و Actionها

Sequence Flow مسیر حرکت اجرای Process از یک Node به Node بعدی است. هر مسیر می‌تواند یک Action داشته باشد؛ Action انتخاب قابل ارائه به کاربر است و دارای Name، Icon و Color است. عنوان خود Sequence Flow، شناسه آن و Action مرتبط را جدا از هم تنظیم کنید. شناسه‌ای مانند Flow\_05s2tc7 برای تشخیص همان اتصال در مدل به کار می‌رود.

## Sequence Flow و ارتباط آن با Action

1.  Sequence Flow موردنظر را در بوم انتخاب کنید و پنل تنظیمات را باز کنید.
2.  در قسمت عنوان، متن مسیر را وارد کنید. ویرایشگر توضیحات برای توضیح مسیر در دسترس است.
3.  در «مدیریت اقدامات» یک Action موجود را انتخاب کنید یا در صورت فعال بودن دکمه، Action جدید بسازید.
4.  برای تغییر Action انتخاب‌شده از «ویرایش اقدام» استفاده کنید؛ عنوان اقدام، رنگ و Icon را تنظیم و ذخیره کنید.
5.  پس از بستن ویرایشگر Action، تنظیمات مسیر و مدل را طبق روش ذخیره استودیو ثبت کنید.

تعریف Action «ادامه» برای Sequence Flow؛ ویرایش عنوان، رنگ و Icon در همان پنل

| کنترل | کاربرد و جزئیات |
| --- | --- |
| عنوان | عنوان اتصال روی مدل؛ با عنوان Action اشتباه نشود. |
| توضیحات | ویرایشگر متن غنی با ابزارهای قالب‌بندی متن، فهرست، لینک و نمای HTML. |
| مدیریت اقدامات | Dropdown انتخاب Action، فلش بازکردن فهرست و × پاک‌کردن انتخاب. |
| ویرایش اقدام | بازکردن ویرایشگر Action انتخاب‌شده. |
| اقدام جدید | ساخت Action؛ در حالت نمایش‌داده‌شدهٔ ویرایش، این دکمه غیرفعال است. این وضعیت را به همه شرایط تعمیم ندهید. |
| عنوان اقدام | نام قابل نمایش، مانند ادامه یا عدم تأیید. |
| رنگ | در نمونه `rgba(0, 255, 217, 1)` برای ادامه انتخاب شده است. |
| Icon | نمونه `fa fa-save` با نماد ذخیره؛ نام Icon را دقیق انتخاب کنید. |
| ذخیره / بستن | ذخیره تغییرات Action یا بستن پنل آن. |

## Action Based Gateway و نمایش اقدام در User Task

در زنجیره User Task → Exclusive Gateway → Sequence Flow Actions، اگر برای مسیرهای خروجی Gateway شرط مستقلی تعریف نشده باشد، انتخاب Action کاربر مسیر بعدی را تعیین می‌کند. این کاربرد Exclusive Gateway در GraphBPMS، Action Based است. Actionها در User Task قبل از Gateway قابل نمایش‌اند.

وجود User Task قبل از Gateway به‌تنهایی دلیل حذف هر نوع شرط در همه مدل‌ها نیست؛ این توضیح مربوط به سناریوی مشخصی است که تصمیم را Action کاربر می‌گیرد و Condition مستقل مسیرها تعریف نشده است. برای سناریوی Condition Based، تنظیمات شروط Gateway را جداگانه انجام دهید.

[![گزینه‌های نوع نمایش اقدامات در User Task: لیست انتخابی، تک‌انتخابی و لیستی از دکمه‌ها](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=45EA9ED1-FB9F-446C-B89A-0BAD96D77B62)](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=45EA9ED1-FB9F-446C-B89A-0BAD96D77B62 "بازکردن تصویر در اندازه اصلی")

گزینه‌های نوع نمایش اقدامات در User Task: لیست انتخابی، تک‌انتخابی و لیستی از دکمه‌ها

| نوع نمایش | رفتار در User Task |
| --- | --- |
| به صورت لیست انتخابی | Actionها در فهرست انتخاب ارائه می‌شوند. |
| به صورت تک انتخابی | کاربر Action را در حالت انتخابی/تیکی مشخص می‌کند. |
| به صورت لیستی از دکمه‌ها | برای Actionها دکمه نمایش داده می‌شود. |

نام، Icon و Color تعریف‌شده برای Action در UI User Task منعکس می‌شوند. رنگ Action هم برای تشخیص مسیر در Studio Designer و هم برای تشخیص اقدام کاربر نهایی معنا دارد؛ در نمونه مسیر «تأیید» سبز و «عدم تأیید» قرمز است. رنگ، جانشین منطق انتخاب مسیر یا شرط نیست؛ تنظیم Action و ارتباط صحیح Sequence Flow باید برقرار باشد.

در صفحه تنظیم یک خروجی، نام Action انتخاب‌شده به عنوان آن خروجی نمایش داده می‌شود؛ در نبود Action، شناسه Sequence خروجی ملاک نمایش است. پنل خروجی بخش «تنظیمات شروط» و بخش «تنظیمات اعلان شرح ارجاع» دارد. در حالت Action Based نشان‌داده‌شده، سازنده شرط خالی است.

مسیر «ارسال پیامک» با تنظیم مستقل شرح ارجاع سفارشی

برای شرح ارجاع سفارشی، کلید مربوط را فعال کنید، نوع شرح ارجاع را انتخاب و متن را وارد کنید. فعال بودن این قابلیت و مقدار متن به همان تنظیم مسیر وابسته است. «ذخیره» تغییرات را ثبت می‌کند و «بستن» پنجره را می‌بندد.

## تنظیمات بازگشت: بازگشت بدون ثبت اطلاعات فرم

در سناریوی Action Based، تنظیم «بازگشت بدون ثبت اطلاعات فرم» روی Sequence Flow مشخص می‌کند کلیک روی Action همان مسیر چه اثری بر ثبت Form داشته باشد. این تنظیم برای خروجی‌ای مانند «عدم تأیید» یا مسیر بازگشت به کار می‌رود و باید روی همان مسیر فعال شود.

[![فعال بودن «بازگشت بدون ثبت اطلاعات فرم» برای Action «عدم تأیید» در خروجی Exclusive Gateway](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=6CA02740-5A43-455E-93E8-16EB1C487662)](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=6CA02740-5A43-455E-93E8-16EB1C487662 "بازکردن تصویر در اندازه اصلی")

فعال بودن «بازگشت بدون ثبت اطلاعات فرم» برای Action «عدم تأیید» در خروجی Exclusive Gateway

اگر کاربر روی Action این Sequence Flow کلیک کند، User Task در حالت `Add` یا `Edit` باشد و Form از نوع `Tableless` نباشد، با فعال بودن این گزینه Variable Log مربوط انجام می‌شود ولی اطلاعات Form ذخیره نمی‌شوند.

| حالت User Task | نتیجه عبور از همین Action با گزینه فعال |
| --- | --- |
| Add / جدید | هیچ Record جدیدی در Form ایجاد نمی‌شود؛ Variable Log مربوط انجام می‌شود. |
| Edit / ویرایش | Record موجود با اطلاعات جاری Form ویرایش نمی‌شود؛ Variable Log مربوط انجام می‌شود. |
| View / نمایش | شرط کاربرد تشریح‌شده Add یا Edit است؛ این قاعده ثبت داده را به View تعمیم ندهید. |
| Tableless | قاعده فوق به Form غیر Tableless محدود است؛ از آن رفتار ذخیره در Tableless نتیجه نگیرید. |

این رفتار فقط برای همان Action/مسیر اعمال می‌شود. فعال‌کردن آن روی «عدم تأیید» به معنی غیرفعال شدن ذخیره برای Action «تأیید» یا سایر مسیرها نیست.

### سناریوی کنترل نتیجه

1.  در User Task جدید، اطلاعات نمونه وارد و مسیر بازگشتِ دارای گزینه فعال را انتخاب کنید؛ ایجاد نشدن Record جدید و انجام Variable Log را بررسی کنید.
2.  در حالت Edit، پیش از اقدام مقدار Record موجود را یادداشت کنید، سپس مقدار فرم را تغییر دهید و Action بازگشت را بزنید؛ داده ذخیره‌شده Record نباید با ورودی جاری جایگزین شود.
3.  رفتار Actionهای دیگر را مستقل بررسی کنید؛ از تنظیم یک مسیر برای آن‌ها نتیجه‌گیری نکنید.

## شرح ارجاع سفارشی روی Sequence Flow

بخش «تنظیمات اعلان شرح ارجاع» در تنظیمات مسیر، گزینهٔ «استفاده از شرح ارجاع سفارشی»، نوع اعلان و متن انتخابی را در کنار شرط مسیر در اختیار طراح می‌گذارد. نوع اعلان این نمونه «موفقیت آمیز» است.

**تفاوت نسخه:** تصویر، تنظیم قدیمی فیلد `@@SavedData:FormData['IsOk']` با مقدار `true` را نشان می‌دهد. در قرارداد فعلی تنظیم شروط Gateway، مقادیر `True` و `False` پذیرفته نمی‌شوند؛ به‌جای آن‌ها از `1` و `0` استفاده کنید. مقدار `true` تصویر را در شرط جاری کپی نکنید.

[![تنظیم قدیمی شرح ارجاع سفارشی روی مسیر تأیید؛ مقدار true در این تصویر برای قرارداد فعلی قابل کپی نیست و شرط باید با ۰/۱ تنظیم شود.](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=3530E081-7206-4387-A179-CF73A3299FAE)](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=3530E081-7206-4387-A179-CF73A3299FAE "بازکردن تصویر در اندازه اصلی")

تنظیم قدیمی شرح ارجاع سفارشی روی مسیر تأیید؛ مقدار true در این تصویر برای قرارداد فعلی قابل کپی نیست و شرط باید با ۰/۱ تنظیم شود.

## نوع اعلان شرح ارجاع مسیر

نوع شرح ارجاع سفارشی در این پنجره سه گزینهٔ «موفقیت آمیز»، «هشدار» و «خطا» دارد. این انتخاب همراه متن اختیاری قرار دارد. نوع اعلان، مستقل از نتیجهٔ واقعی اجرای سرویس یا اسکریپت است؛ انتخاب عنوان «خطا» به‌تنهایی شاهد وقوع استثنا نیست.

**تفاوت نسخه:** مقدار Boolean نمای قدیمی تصویر، الگوی قابل کپی برای قرارداد فعلی نیست؛ شرط فعلی Gateway را با `0` یا `1` تنظیم کنید.

[![فهرست نوع شرح ارجاع سفارشی روی مسیر: موفقیت‌آمیز، هشدار و خطا؛ شرط Boolean قدیمی تصویر باید در قرارداد فعلی با ۰/۱ نوشته شود.](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=5D995A7C-C3A6-422C-9B49-7D0D3AF1D83E)](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=5D995A7C-C3A6-422C-9B49-7D0D3AF1D83E "بازکردن تصویر در اندازه اصلی")

فهرست نوع شرح ارجاع سفارشی روی مسیر: موفقیت‌آمیز، هشدار و خطا؛ شرط Boolean قدیمی تصویر باید در قرارداد فعلی با ۰/۱ نوشته شود.

## Action مشترک و ترتیب نمایش

Name، Color و Icon متعلق به Action انتخاب‌شده‌اند. اگر یک Action در چند مسیر استفاده شده باشد، تغییر مشخصات آن می‌تواند در مسیرهای استفاده‌کننده بازتاب یابد؛ قبل از تغییر، محل‌های مصرف را بررسی کنید. تنظیمات بازگشت و الزام شرح به Sequence Flow همان مسیر مربوط‌اند.

اولویت Action برای نظم نمایش انتخاب‌هاست؛ از جای پیکان روی بوم یا ترتیب نمایش دکمه‌ها، اولویت ارزیابی شرط Gateway را نتیجه نگیرید.

## مثال الزام شرح فقط برای برگشت و رد

در بررسی مرخصی، توضیحی مانند «مدت درخواست را کوتاه‌تر کنید» باید همراه برگشت به درخواست‌کننده برسد. برای این رفتار، دریافت شرح را در User Task بررسی فعال کنید و نمایش شرح دریافتی را در User Task درخواست‌کننده تنظیم کنید. در اولین ورود که شرح قبلی وجود ندارد، پیامی برای نمایش نیست.

| Action | الزام عمومی شرح در User Task | الزام شرح روی Sequence Flow | رفتار مورد انتظار |
| --- | --- | --- | --- |
| تأیید | خاموش | خاموش | ثبت بدون شرح مجاز است. |
| برگشت برای اصلاح | خاموش | روشن | بدون شرح، Validation مانع این Action می‌شود. |
| عدم تأیید کامل | خاموش | روشن | دلیل رد نهایی باید وارد شود. |

اگر الزام عمومی User Task را روشن نگه دارید، تأیید نیز شرح می‌خواهد؛ برای الزام فقط در دو مسیر، تنظیم مسیرها را به کار ببرید. نوع شرح مانند Success، Warning یا Error، ظاهر پیام را تعیین می‌کند و جای انتخاب Action را نمی‌گیرد.

داشتن Action برای هر Sequence Flow اجباری نیست. در یک مسیر ساده می‌توان بدون Action اختصاصی ادامه داد؛ زمانی که کاربر باید میان نتایج تصمیم بگیرد، نام‌گذاری روشن مسیرها و Actionهای آن‌ها ضروری است.
