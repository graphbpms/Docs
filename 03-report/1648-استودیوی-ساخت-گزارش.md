# استودیوی ساخت گزارش در GraphBPMS

مسیر ناوبری: راهبر سیستم ← گزارش‌ساز ← استودیوی ساخت گزارش

**استودیوی ساخت گزارش (Report Studio)** محیط اصلی طراحی، ساخت و پیکربندی گزارش‌ها در سامانه GraphBPMS است. در این محیط، طراح بدون نیاز به درگیری با کدهای پیچیده، منابع داده را به گزارش متصل می‌کند، پارامترها و فیلترهای ورودی را تعریف می‌نماید، ستون‌های جدول را نام‌گذاری و مرتب کرده و با بهره‌گیری از فرمول‌ساز و توابع محاسباتی، ساختار نهایی داده‌ها را شکل می‌دهد. همچنین امکان تعبیه دکمه‌های عملیاتی برای باز کردن فرم‌ها و پیش‌نمایش زنده جدول داده‌ها پیش از انتشار نهایی فراهم شده است. در این آموزش، مراحل طراحی یک گزارش استاندارد از اولین گام ورود به استودیو تا ثبت و مشاهده خروجی در پیشخوان را به صورت گام‌به‌گام بررسی می‌کنیم.

* * *

## ۱. ورود به محیط استودیو، نوار ابزار بالا و تنظیمات عمومی شناسنامه گزارش

برای آغاز طراحی یک گزارش تحلیلی جدید یا ویرایش ساختار گزارش‌های پیشین، از صفحه پیشخوان مدیریت گزارش‌ها (`ReportManager`) بر روی دکمه آبی‌رنگ و شاخص **«ایجاد گزارش»** در بالا سمت چپ کلیک می‌کنیم.

![پیشخوان مدیریت گزارش‌ها و دکمه ایجاد گزارش](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=C07B28B8-CDF1-4E67-9797-F06709AA2AC6)

پیشخوان مدیریت گزارش‌ها (ReportManager) — دکمه آبی «ایجاد گزارش» در نوار ابزار بالا (مشخص‌شده با کادر قرمز)

با کلیک بر روی این دکمه، صفحه استودیوی ساخت گزارش به آدرس `ReportBuilderStudio` گشوده می‌شود. در بدو ورود، بوم طراحی به صورت خالی بارگذاری شده و کلیه ابزارهای مدیریتی و پیکربندی در دسترس طراح قرار می‌گیرد:

![نمای اولیه بوم استودیوی ساخت گزارش](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=68E073E9-B5C7-4631-AA87-6C6D55F2F6D6)

نمای اولیه استودیوی ساخت گزارش (ReportBuilderStudio) شامل نوار ابزار بالا، تب‌های اصلی بوم و پنل تنظیمات در سایدبار سمت راست

### اجزای بنیادین هدر و بوم استودیو

-   **نوار ابزار بالا (Header Toolbar):** شامل سه دکمه حیاتی مدیریت چرخه عمر گزارش:
    -   **ذخیره (دکمه سبز رنگ):** ذخیره‌سازی موقت تغییرات اعمال‌شده بر روی سرور بدون خروج از استودیو، جهت جلوگیری از اتلاف داده‌ها حین طراحی‌های طولانی.
    -   **ذخیره و بازگشت (دکمه آبی رنگ):** اعتبارسنجی نهایی ساختار گزارش، کامپایل تنظیمات، ذخیره قطعی در پایگاه‌داده و هدایت مجدد کاربر به پیشخوان مدیریت گزارش‌ها.
    -   **بازگشت (دکمه خاکستری):** لغو تغییرات ذخیره‌نشده و خروج مستقیم از محیط استودیو.
-   **تب‌های راهبردی بالای بوم:**
    -   **تب تنظیمات منبع:** بوم اصلی مهندسی گزارش شامل ویرایش مشخصات منابع داده، مدیریت پارامترهای ورودی، فرم‌دهی ستون‌های خروجی و افزودن ستون‌های سفارشی عملیاتی.
    -   **تب پیش‌نمایش منبع:** محیط شبیه‌ساز زنده (Live Sandbox) جهت تست عملکرد فیلترها، اجرای کوئری با پارامترهای دلخواه و مشاهده گرید رندرشده پیش از انتشار رسمی گزارش.
-   **پنل ابزار سمت راست (Sidebar Panels):** نوار عمودی تب‌های ساختاری شامل تنظیمات عمومی، منابع داده، سطوح دسترسی، اعلان‌ها و ابزارهای مرتبط.

### پیکربندی شناسنامه گزارش در تب «تنظیمات عمومی»

نخستین گام در طراحی هر گزارش، ثبت مشخصات شناسنامه‌ای و تعیین هویت سازمانی آن در تب **«تنظیمات عمومی»** (آیکن چرخ‌دنده در بالای سایدبار) است. در حالت اولیه، این فیلدها خالی هستند:

![پنل تنظیمات عمومی در حالت اولیه](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=1B5E165F-7033-4652-9582-C403A1E7BE4A)

پنل تنظیمات عمومی (General Settings) در حالت اولیه پیش از تکمیل مشخصات شناسنامه‌ای گزارش

در سناریوی کارگاه این دانشنامه، هدف پیاده‌سازی یک گزارش جامع عملیاتی برای مانیتورینگ پروژه‌های عمرانی و تأسیساتی به همراه ریز صورت‌وضعیت‌های مالی آن‌هاست. لذا فیلدهای تب تنظیمات عمومی را به شرح زیر تکمیل می‌کنیم:

## ۲. تب منابع داده: اتصال منبع داده به گزارش و ابزارهای ساخت درجا در استودیو

در گزارش‌ساز GraphBPMS، داده‌ها از طریق **«منابع داده» (Data Sources / Providers)** مدیریت می‌شوند. دومین تب در سایدبار سمت راست استودیو با آیکن دیتابیس، **«منابع داده»** نام دارد. با ورود به این تب، امکان اتصال یک یا چند منبع داده به گزارش فراهم می‌گردد:

![تب منابع داده و دکمه افزودن منبع داده](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=71BF4022-6D4B-40CD-A7C6-43005B98BF52)

تب اختصاصی «منابع داده» در سایدبار استودیو و دکمه آبی‌رنگ «+ افزودن منبع داده»

با کلیک بر روی دکمه **«+ افزودن منبع داده»**، یک کارت آکاردئونی جدید در سایدبار ایجاد می‌شود. عنوان این منبع را (که در سناریوی کارگاه، جدول اصلی پروژه‌هاست) **«لیست پروژه ها (master)»** قرار می‌دهیم و بر روی دکمه آبی‌رنگ **«اتصال داده»** کلیک می‌کنیم:

![کارت منبع داده مستر و دکمه اتصال داده](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=01C29D13-6315-4992-BCC8-D2B20EFF19B5)

ایجاد کارت آکاردئونی اولین منبع داده با عنوان «لیست پروژه ها (master)» و کلیک روی دکمه «اتصال داده»

### دو مسیر کلیدی پنجره مدیریت منبع داده: منابع موجود در برابر ایجاد درجا

با فشردن دکمه اتصال داده، پنجره مودال **«مدیریت منبع داده»** باز می‌شود که دو مسیر راهبردی را پیش روی طراح قرار می‌دهد:

![پنجره مودال مدیریت منبع داده](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=C795FBAC-B45A-4227-AB5F-E834E7EBD7E2)

پنجره مودال مدیریت منبع داده شامل دو مسیر راهبردی: «منابع داده موجود» (انتخاب پرووایدر) و «ایجاد منبع داده» (ساخت درجا)

#### ۱. ایجاد منبع داده درجا (On-the-Fly Creation)

یکی از درخشان‌ترین ویژگی‌های استودیوی GraphBPMS این است که اگر طراح در حین ساخت گزارش متوجه شود که به کوئری یا وب‌سرویس جدیدی نیاز دارد، ملزم به ترک استودیو و بازگشت به منوی Providers نیست. با کلیک بر روی کاشی **«ایجاد منبع داده»**، پنجره ساخت مستقیم پرووایدر با پشتیبانی از تنوع گسترده‌ای از منابع داده‌ای گشوده می‌شود:

![پنجره ساخت درجا منبع داده در استودیو](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=8DF2CC6D-FBFF-468A-A349-5C3ACA37BFC4)

پنجره ساخت مستقیم منبع داده در استودیو با امکان انتخاب انواع منابع بانک اطلاعاتی (کوئری، پروسیجر، تابع، گزینه‌ها، ویرایشگر پیشرفته) و وب‌سرویس

-   **دسته‌بندی بانک اطلاعاتی (Database Providers):**
    -   **کوئری (Query):** نگارش مستقیم دستورات استاندارد `SELECT` روی جداول پایگاه‌داده به همراه متغیرهای شرطی با علامت `@`.
    -   **رویه ذخیره‌شده (StoredProcedure):** اتصال مستقیم به پروسیجرهای از پیش کامپایل‌شده در SQL Server برای پردازش‌های سنگین و پرترافیک.
    -   **تابع (Function):** فراخوانی توابع اسکالر یا توابع جدولی (Table-Valued Functions).
    -   **گزینه‌ها (Options):** محیط بصری فیلتر و واکشی داده‌ها بدون نیاز به نگارش دستی کدهای SQL.
    -   **ویرایشگر پیشرفته (Advanced Editor):** نگارش اسکریپت‌های پیچیده چندمرحله‌ای T-SQL با جداول موقت و متغیرهای کنترلی.
    -   **موجودیت سیستم (System Entity):** اتصال خودکار به ساختار داده‌ای فرم‌ها و رکوردهای گردش کار GraphBPMS.
-   **دسته‌بندی وب‌سرویس (Web Service Providers):** اتصال مستقیم به سرویس‌های وب برون‌سازمانی، RESTful APIها و سرویس‌های SOAP جهت دریافت بلادرنگ داده‌های مالی و انبار از سیستم‌های ERP.

#### ۲. انتخاب از منابع داده موجود (پرووایدر پروژه‌ها)

در سناریوی کارگاه ما، منابع داده قبلاً در کارگاه عملیاتی پیشخوان ایجاد و تست شده‌اند. با کلیک بر روی کاشی **«منابع داده موجود»**، فهرست پرووایدرها لود می‌شود. منبع داده با عنوان **«اطلاعات پروژه ها Master»** (متصل به مدل داده‌ای پروژه‌ها) را جستجو و انتخاب نموده و بر روی دکمه «ذخیره» کلیک می‌کنیم:

![انتخاب منبع داده موجود اطلاعات پروژه‌ها](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=AE66F7C1-3575-4A7C-BC4A-A9A91281DBAB)

فهرست منابع داده موجود — انتخاب منبع داده «اطلاعات پروژه ها Master» و فشردن دکمه ذخیره

### پیکربندی مشخصات منبع در سایدبار: منبع مستقل (Independent)

پس از اتصال منبع، کارت آکاردئونی در سایدبار به‌روزرسانی شده و فیلدهای زیر در آن فعال می‌گردد:

![کارت منبع مستر تنظیم‌شده به عنوان مستقل](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=AE37E447-A02C-4FB1-9B84-D392B40B8CB1)

کارت منبع داده مستر پس از الصاق موفق؛ تنظیم «نوع منبع داده: مستقل» و دکمه‌های ویرایش، اطلاعات، حذف و اتصال مجدد

-   **نوع منبع داده:** برای این منبع، مقدار را بر روی **«مستقل»** قرار می‌دهیم. منبع مستقل منبعی است که خروجی‌های آن وابسته به هیچ رکورد یا سطر دیگری نیست و مستقیماً توسط فیلترهای ورودی گزارش مقداردهی می‌شود.
-   **دکمه‌های ابزار کارت:**
    -   **ویرایش (آیکن مداد):** اصلاح نام نمایشی منبع در بوم.
    -   **اطلاعات (آیکن i):** مشاهده مشخصات فنی و کدهای SQL کوئری منبع.
    -   **حذف (آیکن سطل زباله):** قطع اتصال منبع از گزارش.
    -   **اتصال داده:** جابه‌جایی یا الصاق پرووایدر جایگزین.

💡

معماری منابع داده در گزارش‌های سازمانی

هر گزارش در GraphBPMS می‌تواند از ترکیب چندین منبع داده مستقل و وابسته تشکیل شود. منابع مستقل معمولاً جداول سرجمع، پروژه‌ها یا صورت‌حساب‌های کلان را تشکیل می‌دهند و منابع وابسته، ریز اقلام و تراکنش‌های مرتبط با هر سطر را مدیریت می‌کنند.

## ۳. پیکربندی پارامترهای ورودی، کاتالوگ جامع انواع داده‌ای و تعریف لیست ثابت انتخابی

به محض اتصال منبع داده پروژه‌ها به بوم استودیو، سیستم ساختار کوئری SQL را بررسی کرده و ستون‌ها و پارامترهای آن را در دو بخش مجزا روی بوم مرکزی نمایش می‌دهد:

-   **بخش اول — پارامترهای منبع:** شامل متغیر ورودی کوئری یعنی `CategoryId` که در کوئری با شرط `WHERE (@CategoryId IS NULL OR CategoryId = @CategoryId)` تعریف شده بود. این پارامتر در ابتدا به صورت یک کارت متنی ساده (Text) روی بوم قرار می‌گیرد:

![کارت پارامتر ورودی CategoryId روی بوم](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=29C737A1-DED3-444C-861B-6C6746CBA99D)

بخش پارامترهای منبع روی بوم استودیو شامل کارت متغیر ورودی CategoryId با نوع اولیه Text

-   **بخش دوم — خروجی‌های منبع:** کلیه ۱۱ فیلد خروجی کوئری به ترتیب در قالب کارت‌های افقی مجزا روی بوم رندر می‌شوند:

![خروجی‌های منبع مستر - بخش اول](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=A761B7A9-FDCA-4A7B-858E-0581F33D7830)

کارت‌های خروجی منبع مستر (بخش ۱): فیلدهای Id، ProjectCode، ProjectTitle و CategoryId

![خروجی‌های منبع مستر - بخش دوم](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=9CB889AD-8E10-45EF-94B1-373FFEE92DB5)

کارت‌های خروجی منبع مستر (بخش ۲): فیلدهای CategoryTitle، StartDateShamsi، DueDateShamsi، BudgetAmount و ProgressPercent

پنجره مودال ویرایش پارامتر — انتخاب نوع داده‌ای متنی (Nvarchar)

پس از انتخاب نوع متنی و ذخیره مودال، در پنل سایدبار و در تب **«تنظیمات اختصاصی»**، گزینه‌های جامعی برای کنترل داده‌های متنی فعال می‌گردد:

![تنظیمات اختصاصی پارامتر متنی در سایدبار](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=B0F8FDED-1175-40FE-8740-CB962C7F205D)

پنل تنظیمات اختصاصی پارامتر متنی: مقدار پیش‌فرض، طول رشته، ویرایشگر چندخطی و HtmlEditor، ماسک و بارکد

-   **مقدار پیش‌فرض:** متنی که به صورت اولیه در فیلتر جستجو قرار می‌گیرد.
-   **حداقل و حداکثر طول رشته:** اعمال محدودیت کاراکتری بر روی ورودی کاربر جهت جلوگیری از خطاهای دیتابیس یا ورودی‌های نامعتبر.
-   **سوئیچ چند خطی (Multiline):** تبدیل ورودی به کادر متنی بزرگ (Textarea) برای توضیحات طولانی یا یادداشت‌ها.
-   **ویرایشگر پیشرفته (HtmlEditor):** فعال‌سازی ویرایشگر غنی با قابلیت قالب‌بندی متون (Bold, Italic, Bullet points).
-   **برچسب‌گذاری (TagBox):** امکان ورود کلمات کلیدی متعدد به صورت تگ‌های مجزا.
-   **تنظیمات Mask (ماسک ورودی):** الزام کاربر به رعایت فرمت‌های استاندارد نظیر شماره تلفن یا کد ملی.
-   **خواندن از بارکد:** قابلیت اتصال مستقیم به اسکنر بارکدخوان جهت تسریع ورود داده‌های متنی و کد کالا.
-   **الگوی بهینه کوئری T-SQL:**
    
    ```
    WHERE (@Title IS NULL OR ProjectTitle LIKE N'%' + @Title + '%')
    ```
    

#### ۲. پارامتر عددی (Number / Numeric)

زمانی که فیلتر گزارش نیازمند مقادیر مقداری، آماری یا مالی باشد، در مودال ویرایش پارامتر گزینه دوم یعنی **«Number / عدد»** را برمی‌گزینیم:

![انتخاب نوع عددی Number در پنجره ویرایش پارامتر](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=0A114570-DD30-41B8-BFDF-A6F4FD2F6969)

پنجره مودال ویرایش پارامتر — انتخاب نوع داده‌ای عددی (Number)

با انتخاب این نوع، تب **«تنظیمات اختصاصی»** در سایدبار به پنل کنترل پیشرفته مقادیر ریاضی و عددی تغییر شکل می‌دهد:

![تنظیمات اختصاصی پارامتر عددی در سایدبار](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=155DB5B4-54E4-4AED-86E7-A7D3F75476CB)

پنل تنظیمات اختصاصی پارامتر عددی: تعیین نوع داده عددی، بازه حداقل/حداکثر، گام تغییرات، فرمت‌بندی و حالت اسلایدر

-   **نوع داده عددی (Data Type):** انتخاب زیرنوع‌های دقیق دیتابیس نظیر `Int` (اعداد صحیح)، `BigInt`، `Decimal` یا `Float` (اعداد اعشاری و ارقام ریالی).
-   **بازه حداقل و حداکثر (Min / Max Range):** تعیین دامنه مجاز ارقام ورودی، به عنوان مثال کف بودجه یا سقف درصد پیشرفت (۰ تا ۱۰۰).
-   **گام تغییرات (Step):** گام افزایش/کاهش مقادیر با کلیدهای اسپین‌باکس یا غلطک ماوس (مثلاً گام‌های ۵ تایی یا ۱۰۰۰ تایی).
-   **فرمت نمایشی (Format):** جداسازی سه رقم سه رقم ارقام پولی یا تعیین تعداد ارقام اعشار مجاز.
-   **نمایش اسلایدری (Slider Mode):** تبدیل فیلد ورودی به یک نوار لغزنده بصری، بسیار کارآمد جهت فیلتر درصدهای پیشرفت یا نمرات ارزشیابی.
-   **الگوی بهینه کوئری T-SQL:**
    
    ```
    WHERE (@MinBudget IS NULL OR BudgetAmount >= @MinBudget)
      AND (@MaxBudget IS NULL OR BudgetAmount <= @MaxBudget)
    ```

پنجره مودال ویرایش پارامتر — انتخاب نوع داده‌ای تاریخ (Date)

پس از انتخاب تاریخ و ذخیره، تب **«تنظیمات اختصاصی»** در سایدبار امکانات عمیق بومی‌سازی و مدیریت تقویم را ارائه می‌دهد:

![تنظیمات اختصاصی پارامتر تاریخ در سایدبار](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=BBF9A0C5-6C0C-4C91-9520-DA058830B70C)

پنل تنظیمات اختصاصی پارامتر تاریخ: مدل نمایشی شمسی/میلادی، خروجی دیتابیس، بسته‌شدن پاپ‌آپ و نحوه ورود دیتا

-   **مدل نمایشی (Display Model):** انتخاب سیستم گاه‌شماری تقویم (شمسی، میلادی، قمری).
-   **فرمت خروجی تاریخ (Output Format):** تعیین نحوه ارسال تاریخ به پایگاه‌داده (مثلاً تبدیل خودکار تاریخ شمسی انتخاب‌شده به میلادی استاندارد جهت ذخیره‌سازی در فیلدهای `datetime` دیتابیس).
-   **ترکیب تاریخ و زمان:** سوئیچ فعال‌سازی دریافت همزمان ساعت در کنار تاریخ روز.
-   **نمایش تاریخ روز جاری:** مقداردهی خودکار فیلتر به تاریخ امروز به محض باز شدن گزارش.
-   **بسته شدن Popup بعد از انتخاب:** بستن خودکار پنجره تقویم شمسی بلافاصله پس از کلیک کاربر روی روز مورد نظر.
-   **نحوه درج تاریخ:** انتخاب میان ورود دستی با ماسک کاراکتری (مانند `۱۴۰۵/۰۸/۱۵`) یا باز شدن پنجره انتخاب از تقویم گرافیکی شمسی.
-   **الگوی بهینه کوئری T-SQL برای بازه تاریخی:**
    
    ```
    WHERE (@FromDate IS NULL OR StartDateShamsi >= @FromDate)
      AND (@ToDate IS NULL OR StartDateShamsi <= @ToDate)
    ```

پنجره مودال ویرایش پارامتر — انتخاب نوع داده‌ای زمان (Time)

در تب **«تنظیمات اختصاصی»** سایدبار، کنترل‌های رابط کاربری زمان در دسترس قرار می‌گیرند:

![تنظیمات اختصاصی پارامتر زمان در سایدبار](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=0BD99FCD-473E-43C0-82F7-70BAABCD9169)

پنل تنظیمات اختصاصی پارامتر زمان: زمان پیش‌فرض، سوئیچ زمان جاری، نمایش ساعت آنالوگ و نمایش ثانیه

-   **نوع نمایش:** انتخاب میان ساعت آنالوگ (عقربه‌ای تعاملی) یا ساعت دیجیتال با دکمه‌های بالا/پایین.
-   **نمایش زمان جاری:** ثبت خودکار ساعت کنونی سیستم به عنوان مقدار اولیه فیلتر.
-   **نمایش ثانیه:** امکان دقت‌بخشی به فیلتر بر اساس ثانیه یا اکتفا به ساعت و دقیقه (`HH:MM`).
-   **الگوی بهینه کوئری T-SQL:**
    
    ```
    WHERE (@LogTime IS NULL OR CAST(EventTime AS TIME) >= @LogTime)
    ```

در تب **«تنظیمات اختصاصی»** سایدبار، کنترل رفتار سوئیچ یا چک‌باکس با انعطاف‌پذیری بالایی ارائه شده است:

![تنظیمات اختصاصی پارامتر بلی خیر در سایدبار](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=3E8F757B-3B4F-4602-A148-E1921A543DE8)

پنل تنظیمات اختصاصی پارامتر بلی/خیر: سوئیچ مقدار پیش‌فرض خالی، فعال‌سازی حالت Switch و برچسب‌های متنی سفارشی

-   **مقدار پیش‌فرض خالی (Allow Null / سه حالته):** قابلیتی فوق‌العاده کاربردی که به کاربر اجازه می‌دهد وضعیت فیلتر را در حالت خنثی (تمام رکوردها اعم از بله یا خیر بدون اعمال فیلتر) رها کند.
-   **نمایش به صورت فیلد Switch:** در صورتی که این گزینه فعال (ON) باشد، کنترل ورودی در فرم فیلتر به صورت یک **سوئیچ لغزنده مدرن** رندر می‌شود؛ و در صورتی که غیرفعال (OFF) باشد، فیلتر به صورت **چک‌باکس سنتی تیک‌زدنی** در رابط کاربری ظاهر خواهد شد.
-   **عناوین حالت فعال و غیرفعال:** امکان بومی‌سازی برچسب‌های گزینه‌ها متناسب با حوزه کسب‌وکار (مانند «فعال / راکد»، «تأییدشده / ردشده»، «پرداخت‌شده / معوق»).
-   **الگوی بهینه کوئری T-SQL:**
    
    ```
    WHERE (@IsActive IS NULL OR IsActive = @IsActive)
    ```

## ۵. کارگاه عملی: ساخت گزارش سلسله‌مراتبی و چندمنبعی (Master-Detail)

تا این مرحله، کار با ساختار پایه استودیو، اتصال اولین منبع داده، تعریف پارامترهای فیلتر و مشاهده خروجی در قالب یک جدول ساده را تجربه کردیم. اکنون در این کارگاه عملی، به سراغ یکی از کاربردی‌ترین قابلیت‌های استودیو می‌رویم: **طراحی گزارش‌های سلسله‌مراتبی و پیوند چند منبع داده به یکدیگر (Master-Detail)**.

💡

مفهوم گزارش Master-Detail چیست و چرا به آن نیاز داریم؟

در دنیای واقعی کسب‌وکارها، داده‌ها همیشه تک‌سطحی نیستند؛ بلکه اغلب رابطه‌ای به شکل **«والد و فرزند» (Parent-Child)** دارند:

-   **سطح اصلی یا والد (Master):** اطلاعات کلان هر «پروژه» نظیر نام پروژه، کارفرما و بودجه کلان آن است.
-   **سطح تفصیلی یا فرزند (Detail):** ریز «صورت‌وضعیت‌ها، فاکتورها و اقلام هزینه» است که برای هر پروژه صادر شده‌اند.

اگر بخواهیم تمام این اقلام را در یک جدول ساده قرار دهیم، عنوان پروژه به تعداد تک‌تک هزینه‌هایش تکرار می‌شود و جدول به شدت شلوغ و ناخوانا می‌گردد. اما در **گزارش Master-Detail**، کاربر در نگاه اول فقط لیست تمیز پروژه‌ها را می‌بیند؛ و هر زمان که روی علامت مثبت (**+**) کنار یک پروژه کلیک کند، زیرجدول اقلام صورت‌وضعیتِ همان پروژه به صورت آکاردئونی باز می‌شود.

🔗

راز پیوند دو منبع در استودیو: نگاشت پارامتر (Parameter Binding)

برای ایجاد این ارتباط در استودیوی GraphBPMS، نیازی به نوشتن کوئری‌های پیچیده SQL JOIN نیست. سازوکار کار بسیار ساده و بصری است:

1.  منبع داده دوم (دیتیل) دارای یک پارامتر ورودی به نام `@ProjectId` در کوئری خود است (`WHERE ProjectId = @ProjectId`).
2.  در استودیو مشخص می‌کنیم که این پارامتر، مقدار خود را مستقیماً از ستون کلید اصلی منبع والد (یعنی ستون `Id` پروژه) دریافت کند.
3.  با کلیک کاربر بر روی هر ردیف پروژه، سیستم مقدار `Id` آن سطر را برداشته، به پارامتر `@ProjectId` تزریق می‌کند و در کسری از ثانیه، ریز اقلام مرتبط را واکشی می‌نماید.

مراحل ۵‌گانه اجرای کارگاه Master-Detail در استودیو:

۱. افزودن منبع دوم (اقلام هزینه) ← ۲. تنظیم ماهیت به منبع «وابسته» ← ۳. نگاشت پارامتر کلید (Parameter Binding) ← ۴. آزمون و پیش‌نمایش اقلام ← ۵. فارسی‌سازی ستون‌های دیتیل

۱ منبع داده والد (Master)

**جدول پروژه‌ها** موجودیت اصلی پایگاه داده

⬇

**کلید سطر: Id** کلید اصلی ارسال‌شونده به فرزند

۲ نگاشت رابطه‌ای (Binding)

اتصال خودکار کلید

Id → @ProjectId

۳ منبع داده فرزند (Detail)

**شرط فیلتر پارامتریک:** `WHERE ProjectId = @ProjectId`

⬇

**صورت‌وضعیت‌ها و هزینه‌ها** واکشی برخط اقلام متناظر پروژه

۴ نمایش نهایی برای کاربر

**جدول کلان پروژه‌ها** سطرهای والد با آیکون بازشو

⬇

**زیرجدول بازشونده اقلام \[+\]** رندر بلادرنگ زیر سطر انتخاب‌شده

معماری جریان داده و نگاشت پارامتر در سناریوی کارگاه Master-Detail پلتفرم GraphBPMS

## ۶. جعبه‌ابزار پیشرفته ستون‌های داده: تنظیمات بصری، فرمول‌ساز، توابع تجمیعی و Custom JS

استودیوی ساخت گزارش GraphBPMS دارای مجموعه‌ای غنی از ابزارهای مهندسی لایه نمایش است که امکان پیاده‌سازی محاسبات پویا، قالب‌بندی‌های شرطی و تغییر چیدمان ستون‌ها را بدون نیاز به کدهای سمت دیتابیس مهیا می‌سازد:

![کنترل‌های تفصیلی کارت فیلد خروجی](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=F6578872-DCDE-4422-A27C-9504241314E0)

نمای تفصیلی کارت فیلد خروجی: عنوان فارسی، عرض ستون (px)، توابع تجمیعی و چک‌باکس‌های نمایش، گروه‌بندی و ستون ثابت

### کنترل‌های بنیادین هر کارت خروجی

-   **عنوان ستون:** برچسب نمایشی ستون در گرید نهایی.
-   **اندازه ستون (Width):** تعیین عرض ستون بر حسب پیکسل. در صورت درج مقدار `0`، سیستم عرض ستون را متناسب با محتوا به صورت خودکار تنظیم می‌کند.
-   **توابع تجمیعی (Aggregates):** فعال‌سازی محاسبات آماری خودکار در پاورقی گرید شامل:
    -   `Sum`: محاسبه مجموع مقادیر ستون (ایده‌آل برای فیلدهای بودجه و مبالغ صورت‌وضعیت).
    -   `Count`: شمارش تعداد ردیف‌ها.
    -   `Avg`: میانگین‌گیری عددی.
    -   `Min` / `Max`: استخراج کمترین و بیشترین مقدار ثبت‌شده.
-   **چک‌باکس «نمایش»:** فعال یا غیرفعال کردن رندر ستون در جدول خروجی بدون حذف آن از ساختار کوئری.
-   **چک‌باکس «گروه‌بندی»:** فعال‌سازی قابلیت کشیدن ستون به نوار بالای جدول جهت گروه‌بندی چندسطحی داده‌ها.
-   **چک‌باکس «ستون ثابت» (Freeze Column):** قفل کردن ستون در هنگام اسکرول افقی (بسیار کاربردی برای ستون‌های شناسه و کد پروژه در جداول عریض).
-   **دستگیره جابه‌جایی (Drag Handle):** نماد ۶ نقطه در سمت راست هر کارت جهت تغییر ترتیب قرارگیری ستون‌ها در گرید با کشیدن و رها کردن.

قاعده طلایی معماری Custom JS: تخصیص به متغیر result به جای دستور return

همان‌طور که در کامنت نمونه اولیه محیط ادیتور مشاهده می‌شود (`// var result = args.row.ColumnName;`)، موتور ارزیابی جاوااسکریپت GraphBPMS در یک کانتکست ایزوله اجرا شده و در پایان پردازش، مقدار نهایی را مستقیماً از متغیر `result` واکشی می‌کند. لذا طراحان **هرگز نباید از دستور `return` در سطح بالای کد استفاده کنند**، بلکه نتیجه محاسبات یا تگ‌های HTML باید مستقیماً درون متغیر `result` مقداردهی شوند. همچنین دسترسی به فیلدهای سطر جاری منحصراً از طریق آبجکت `args.row` صورت می‌پذیرد.

![درج کدهای جاوااسکریپت در ویرایشگر کاستوم کد](https://portal.graphbpms.ir/Archive/GetFileAnonymous?id=C55E6736-9B13-46B9-B75A-D828C8EABA33)

درج منطق محاسباتی تاریخ سررسید و درصد پیشرفت در محیط ویرایشگر کاستوم کد

قطعه‌کد استاندارد و تست‌شده جهت کپی و استفاده در این سناریو:

```
// ۱. دریافت تاریخ سررسید و درصد پیشرفت از سطر جاری
var dueDateStr = args.row.DueDateShamsi;
var progress = Number(args.row.ProgressPercent) || 0;
var result = "";

// ۲. در صورت تکمیل بودن ۱۰۰٪ پروژه
if (progress >= 100) {
    result = '<div style="line-height: 1.4;">' +
             '  <span style="color: #15803d; font-weight: bold;">✓ تحویل داده شده</span>' +
             '  <div style="font-size: 11px; color: #15803d; margin-top: 2px;">(پیشرفت: ۱۰۰٪)</div>' +
             '</div>';
} else if (!dueDateStr) {
    result = '<span style="color: #94a3b8;">تاریخ نامشخص</span>';
} else {
    // ۳. تجزیه تاریخ سررسید شمسی (مثال: 1405/08/15)
    var parts = String(dueDateStr).split('/');
    var dueYear = parseInt(parts[0], 10);
    var dueMonth = parseInt(parts[1], 10);
    var dueDay = parseInt(parts[2], 10);

    // ۴. استخراج تاریخ امروز شمسی به صورت ریاضی خالص از روی تقویم میلادی
    var d = new Date();
    var gy = d.getFullYear() - 1600;
    var gm = d.getMonth();
    var gd = d.getDate() - 1;

    var g_days = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31];
    var j_days = [31, 31, 31, 31, 31, 31, 30, 30, 30, 30, 30, 29];

    var g_day_no = 365 * gy + Math.floor((gy + 3) / 4) - Math.floor((gy + 99) / 100) + Math.floor((gy + 399) / 400);
    for (var i = 0; i < gm; ++i) g_day_no += g_days[i];
    if (gm > 1 && ((gy % 4 == 0 && gy % 100 != 0) || (gy % 400 == 0))) ++g_day_no;
    g_day_no += gd;

    var j_day_no = g_day_no - 79;
    var j_np = Math.floor(j_day_no / 12053);
    j_day_no %= 12053;

    var jy = 979 + 33 * j_np + 4 * Math.floor(j_day_no / 1461);
    j_day_no %= 1461;

    if (j_day_no >= 366) {
        jy += Math.floor((j_day_no - 1) / 365);
        j_day_no = (j_day_no - 1) % 365;
    }

    var jm = 0;
    for (var j = 0; j < 11 && j_day_no >= j_days[j]; ++j) {
        j_day_no -= j_days[j];
        jm = j + 1;
    }
    var jd = j_day_no + 1;
    var todayMonth = jm + 1;

    // ۵. تبدیل هر دو تاریخ به روز مطلق از مبدأ جهت محاسبه دقیق روزهای باقیمانده
    var dueTotalDays = (dueYear - 1400) * 365 + Math.floor((dueYear - 1400) / 4) + (dueMonth <= 6 ? (dueMonth - 1) * 31 : 186 + (dueMonth - 7) * 30) + dueDay;
    var todayTotalDays = (jy - 1400) * 365 + Math.floor((jy - 1400) / 4) + (todayMonth <= 6 ? (todayMonth - 1) * 31 : 186 + (todayMonth - 7) * 30) + jd;

    var daysLeft = dueTotalDays - todayTotalDays;

    var statusText = "";
    var statusColor = "";
    if (daysLeft < 0) {
        statusText = "⚠️ " + Math.abs(daysLeft) + " روز گذشته";
        statusColor = "#dc2626";
    } else if (daysLeft <= 30) {
        statusText = "⏳ " + daysLeft + " روز (فوری)";
        statusColor = "#d97706";
    } else {
        statusText = "⏱ " + daysLeft + " روز باقیمانده";
        statusColor = "#0284c7";
    }

    // ۶. تخصیص خروجی نهایی به متغیر result (ترکیب وضعیت مهلت و درصد پیشرفت)
    result = '<div style="line-height: 1.4;">' +
             '  <div style="color: ' + statusColor + '; font-weight: bold;">' + statusText + '</div>' +
             '  <div style="font-size: 11px; color: #475569; margin-top: 2px;">پیشرفت: <strong>' + progress + '%</strong></div>' +
             '</div>';
}
```

##### گام هفتم: درج شاخصه دوم — متغیرهای «سیستمی» (System Context Variables)

دومین شاخصه، **متغیرهای سیستمی** هستند که امکان استخراج اطلاعات بلادرنگ نشست کاربری و بستر اجرایی را بدون کدنویسی فراهم می‌سازند. با انتخاب رادیوباتن «سیستمی»، منوی کشویی مقادیر سیستمی فعال می‌شود:

-   **شناسه کاربر جاری:** کد پرسنلی / شناسه منحصربه‌فرد کاربری که در حال مشاهده گزارش است.
-   **شناسه نقش جاری:** شناسه سمت یا پست سازمانی فعال کاربر.
-   **سازمان جاری:** شناسه دپارتمان یا واحد سازمانی متبوع.
-   **تاریخ جاری:** تاریخ روز سیستم جهت درج زمان ایجاد یا ثبت در خروجی هر سطر.
